# X500 CTBR 궤적 추종 정책 (IQL + sim-DAgger 2회차 / 3회차)

`data_track.csv.gz`(PX4 SITL + Gazebo `gz_x500`, 10만 transition)로 학습한 IQL 정책이다.
간이 시뮬레이터에서 DAgger를 2회 또는 3회 적용했다. **권장 모델은 `dagger3/`이다.**

```
dagger2/  policy.onnx  onnx_validation.json  config.json  sim_eval.json
dagger3/  policy.onnx  onnx_validation.json  config.json  sim_eval.json   ← 권장
```

## 1. 입출력

| | 형식 | 내용 |
|---|---|---|
| 입력 `observations` | float32 `[batch, 25]` | **원시 관측**이다. 정규화가 모델 안에 포함되어 있으므로 따로 정규화하지 않는다. |
| 출력 `actions` | float32 `[batch, 4]` | 결정론적 행동, 범위 `[-1, 1]`, 100 Hz |

관측은 `data_track.csv.gz`의 `obs_0`–`obs_24`와 **완전히 같다**. 좌표 변환, lookahead 같은 추가 피처, 차원 변경을 하지 않았다.
따라서 데이터를 수집한 환경이 내보내는 관측을 그대로 넣으면 된다. DAgger 데이터도 같은 형식으로 생성했다.

| 인덱스 | 내용 | 좌표계 |
|---|---|---|
| 0:3 | 위치 오차 (target − pos) | world |
| 3:12 | 자세 회전행렬 R, row-major (body→world) | – |
| 12:15 | 선속도 | world |
| 15:18 | 각속도 | body |
| 18:22 | **직전 스텝에 실제로 보낸 action** | – |
| 22:25 | 기준 궤적 속도 | world |

행동 변환:
- 추력 N = `(a0 + 1) / 2 × 34.19` (호버 근처 a0 ≈ 0.16)
- roll / pitch / yaw rate [deg/s] = `a1 × 220`, `a2 × 220`, `a3 × 200`

**좌표계:** world는 NWU, body는 FLU다. 데이터셋 관측은 이미 이 좌표계로 변환된 값이다.
- **데이터 수집 코드와 같은 방식으로 관측을 만드는 경우:** 추가 변환 없이 그대로 넣는다.
- **PX4 원시 텔레메트리(NED/FRD)로 관측을 직접 조립하는 경우:** 위치·속도·회전에 `diag(1, −1, −1)` 변환을 적용한 뒤 넣는다(DATASET.md §3).
- **행동을 PX4로 보낼 때:** body rate는 FLU 기준이므로 FRD로 바꿔서 보낸다(pitch·yaw 부호 반전). 수집 코드가 쓰던 변환을 그대로 쓰면 된다.

`obs[18:22]`에는 직전 스텝에 정책이 실제로 보낸 `[-1, 1]` 행동을 넣어야 한다.

```python
import onnxruntime as ort, numpy as np
sess = ort.InferenceSession("dagger3/policy.onnx")
a = sess.run(["actions"], {"observations": obs.astype(np.float32)[None]})[0][0]
```

## 2. ⚠️ 시작 기수(yaw) 조건

관측의 회전행렬에 yaw가 그대로 들어간다. 학습 데이터의 기수는 대부분 **−94° 부근**(PX4 시작 heading, world NWU 기준)이다.
그래서 정책은 그 범위에서만 동작한다.

| 시작 yaw | DAgger×3 추락 |
|---|---|
| −94° ± 60° 안에서 무작위 | **0/50** (오차 0.18 → 0.21 m로 소폭 증가) |
| 완전 무작위 중 60°–120° 벗어난 경우 | 4/17 |
| 완전 무작위 중 120° 이상 벗어난 경우 | 10/13 |

이륙 시 기수를 −94° ± 60° 안에 두어야 한다.
기수와 무관하게 동작시키려면 관측을 yaw 기준 좌표로 회전시켜 재학습하면 된다. 기존 데이터는 오프라인 변환만으로 재사용할 수 있다.

## 3. 결과 (간이 시뮬레이터, 폐루프)

원 또는 8자 궤적(반경 0.8–1.5 m, 주기 6–10 s, DATASET.md §7 조건)을 20초씩 50회 비행했다.
추락 판정 기준은 데이터셋의 terminal 조건과 같다.

| 모델 | 추락 /50 | 평균 오차 (생존) | 최대 오차 |
|---|---|---|---|
| PD expert (데이터 수집 제어기 재구현) | 0 | 0.177 m | 0.51 m |
| IQL (DAgger 없음) | 43 | 0.156 m | 6.89 m |
| 6-모델 앙상블 (DAgger 없음) | 6 | 0.245 m | 5.98 m |
| **DAgger×2** | 1 | 0.176 m | 1.22 m |
| **DAgger×3** | **0** | **0.179 m** | **0.64 m** |

오프라인 검증 action MSE는 DAgger를 할수록 오히려 나빠졌다(0.018 → 0.032 / 0.028).
기록된 행동 적합도는 비행 성능의 지표가 아니다.

## 4. 학습 방법

1. **IQL:** 256×2 MLP, β 3.0, τ 0.85, γ 0.99, smoothness 0.05, 보상 클리핑 없음, 30만 스텝. 비행 단위 분할(검증 비행 2, 3, 4, 18, 20, 34, 35)을 사용했고, terminal만 부트스트랩을 끊었다.
2. **간이 시뮬레이터:** 학습 비행 데이터에서 최소제곱으로 동역학을 식별했다.
   - 각속도: 명령 대비 20–30 ms 지연을 갖는 FIR 응답
   - 추력: 2스텝 지연, 유효 계수 kT 0.415, g 8.21
   - 검증 비행에서의 held-out one-step R²: ω 0.88 / 0.87 / 0.55, v 0.71
   - 기록된 행동을 1초간 open-loop로 재생했을 때 자세 오차 2.4°, 속도 오차 0.35 m/s
3. **DAgger:** 현재 정책으로 시뮬레이터를 비행하고, 방문한 상태마다 PD expert의 행동을 라벨로 붙였다.
   next_obs는 시뮬레이터 복제본을 라벨 행동으로 한 스텝 진행해서 만들었다. 기록된 행동이 상태 전이를 실제로 일으킨 값이 되도록 하기 위해서다.
   - 1회차: 기본 정책 비행, 8.1만 행
   - 2회차: DAgger×1 비행, 19.5만 행
   - 3회차: DAgger×2 비행, 20만 행
   - 매 회차 실제 데이터와 누적 DAgger 데이터로 재학습했다.
